# React 18 신기능 및 동구현 메커니즘 (Concurrent React)

React 18은 동구현(Concurrent Rendering) 아키텍처를 기반으로 렌더링 성능 최적화와 사용자 경험(UX) 개선을 위한 새로운 기능들을 도입했다.

기존 동기적(Synchronous) 렌더링에서 **우선순위에 기반한 중단 가능 렌더링(Interruptible Rendering)**으로의 패러다임 전환이 핵심이다.

---

## 1. Concurrent Rendering (동구현 렌더링)

기존 React는 한 번 렌더링이 시작되면 브라우저의 메인 스레드를 점유하여 렌더링 작업이 완료될 때까지 다른 사용자 입력(타이핑, 클릭 등)을 처리하지 못했다.

React 18의 Concurrent Engine은 다음과 같은 변화를 가져왔다.

- **렌더링 중단 및 재개**: 긴 렌더링 작업 도중 고우선순위 이벤트(사용자 입력을 위한 긴급 업데이트)가 발생하면 진행 중인 렌더링을 중단하고 입력부터 처리.
- **오프스크린 렌더링**: 화면에 보이지 않는 UI를 백그라운드에서 사전에 렌더링 준비.

---

## 2. 주요 신기능 및 API

### 1) Automatic Batching (자동 배치)
기존 React 17은 React 이벤트 핸들러 내부에서만 배치가 적용되었으나, React 18부터는 `Promise`, `setTimeout`, `native event handler` 내부의 상태 변경도 자동으로 하나로 묶어(Batching) 1번만 리렌더링한다.

```javascript
// React 18: setTimeout 내부에서도 1번만 리렌더링 발생
setTimeout(() => {
  setCount(c => c + 1);
  setFlag(f => !f);
}, 1000);
```

### 2) Transitions (`useTransition`, `startTransition`)
상태 업데이트의 우선순위를 명시적으로 분리한다.

- **Urgent Update (긴급 업데이트)**: 글자 입력, 버튼 클릭 등 즉각적 반응이 필요한 작업
- **Transition Update (전환 업데이트)**: 검색 결과 목록 필터링, 차트 변경 등 잠시 지연되어도 되는 작업

```javascript
import { useState, useTransition } from 'react';

function SearchBox() {
  const [isPending, startTransition] = useTransition();
  const [input, setInput] = useState('');
  const [list, setList] = useState([]);

  const handleChange = (e) => {
    // 1. 긴급 업데이트 (입력 창 렌더링)
    setInput(e.target.value);

    // 2. 비긴급 전환 업데이트 (대규모 리스트 필터링)
    startTransition(() => {
      setList(filterHugeData(e.target.value));
    });
  };

  return (
    <div>
      <input value={input} onChange={handleChange} />
      {isPending ? <Spinner /> : <List items={list} />}
    </div>
  );
}
```

### 3) `useDeferredValue`
상태 자체의 업데이트 지연 버전을 생성하여 디바운싱(Debounce) 없이도 유연한 UI 렌더링을 제공한다.

### 4) Suspense SSR & Selective Hydration
서버 사이드 렌더링(SSR) 시 전체 페이지가 HTML로 전송되기를 기다리지 않고, `<Suspense>`로 감싸진 부분은 준비되는 대로 스트리밍 전송 및 개별 하이드레이션(Selective Hydration)을 수행한다.

---

## 3. React 18 신규 Hooks 요약

| Hook | 주요 용도 |
| --- | --- |
| `useTransition` | 상태 업데이트의 우선순위를 비긴급으로 낮춤 (`isPending` 상태 제공) |
| `useDeferredValue` | 값의 업데이트를 지연시켜 고우선순위 렌더링 우선 처리 |
| `useId` | SSR 환경에서도 클라이언트와 100% 일치하는 유니크 ID 생성 |
| `useSyncExternalStore` | 외부 스토어(Zustand, Redux 등) 구독 시 동구현 모드 찢어짐(Tearing) 방지 |
